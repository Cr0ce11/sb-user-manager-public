# 安全设计

## 信任边界

程序以 root 身份运行，因此以下输入均视为不可信：

- 终端输入。
- 运行配置内容和文件路径。
- 远程规则集。
- GitHub API 和 Release 元数据。
- 下载的压缩包及程序。
- 外部迁移包。
- 现有 sing-box 配置和 Nfuse 数据。
- systemd 日志中显示的网络内容。

## 必须保持的安全属性

- 不执行配置文件中的 shell 内容。
- 不跟随敏感配置或状态文件的符号链接。
- 不把秘密写入命令行、日志、诊断报告或 Git 仓库。
- 所有远程下载使用 HTTPS，并在安装前验证 digest。
- 解压前限定预期资产和文件位置，不能信任归档内任意路径。
- 删除操作必须验证目标属于受管目录，拒绝空路径和宽泛系统路径。
- 修改 sing-box、Nfuse 和状态文件时必须能够整体回滚。
- 迁移包必须在解密前验证完整性，解密明文及时清理。
- 经 `run_step_or_rollback` 或 `run_managed_step` 调用的函数不得依赖 `set -e`：Bash 会在条件调用上下文中关闭函数体的 `errexit` 语义。函数内下载、校验、解包、安装、移动、删除或写系统文件的每一步都必须用 `|| return`、`|| die` 或明确条件分支传播失败。

## 高风险变更

以下改动必须在 Pull Request 中单独标记，并增加针对性测试：

- `rm -rf`、`mv`、`install`、`tar` 或系统路径写入。
- `curl`、GitHub Release 解析和自更新。
- root 配置解析、权限和符号链接处理。
- 密码、密钥、证书和迁移加密。
- trap、事务、锁和恢复流程。
- systemd 服务启停。

## 供应链方向

SHA-256 只能证明下载内容与 Release 元数据一致，不能阻止发布后用同一版本号替换附件。Release 必须先以草稿形式上传唯一公开脚本及其 SHA-256 文件，核对 GitHub digest 后一次性发布；同版本已经存在时拒绝覆盖或复用。

发布前读取仓库不可变 Release 设置必须使用只授权当前仓库、仅有 Repository Administration 只读权限的短期 Actions Secret；该密钥不得用于创建、上传或发布 Release。密钥缺失、过期、接口拒绝或设置未启用时必须在创建 Release 前失败关闭。

仓库使用 GitHub 不可变 Release 锁定未来正式版的标签与附件。迁移到公开仓库后重新评估 Artifact Attestations 和 Ruleset；在正式启用前不宣称具备这些保护，也不引入需要自行保管的长期签名私钥。
