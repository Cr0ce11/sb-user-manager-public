# v5 入口集中管理最小 POC 验收方案

## 文档状态

- 关联：[Issue #197](https://github.com/DTB201/sb-user-manager/issues/197)
- 架构依据：[ADR 0005](DECISIONS/0005-entry-authenticated-multi-egress-controller.md)
- 当前状态：仅定义验证计划，尚未部署或取得新架构实测证据
- 正式服务器：不在范围内

## 目的

POC 只回答四个进入实现前的关键问题：

1. 入口完成 AnyTLS 认证后再计费，错误密码和无效认证是否能保持用户用量零增长。
2. 用户在多个受管落地和现有 AnyTLS 外部节点之间切换或分流时，是否共享同一个硬配额且只计费一次。
3. 现有规则优先级、全局/指定用户范围和外部 AnyTLS 出口是否能在入口认证后继续工作。
4. 入口是否能通过最小权限通道安全、幂等、可恢复地管理多台落地。

POC 通过不代表 v5 可以发布。它只允许后续把架构拆成独立 Issue 实现。

## 不在范围内

- 正式业务服务器、正式用户或正式数据。
- 入口高可用和多入口共享配额。
- Web 面板、数据库集群或长期运行的额外控制服务。
- 自动购买域名、修改正式 DNS 或签发正式证书。
- v4 状态自动迁移和 Release 发布。
- entry-controller 中 Shadowsocks、SS2022 + ShadowTLS 的正式兼容结论。
- 未经实测宣称的性能上限。

## 测试资产

使用相互隔离、可随时销毁或恢复快照的 Debian 12 x86_64 测试机：

| 角色 | 数量 | 用途 |
|---|---:|---|
| 入口 | 1 | 公网 443、入口认证、分流、loopback Nfuse 和集中管理 |
| 受管落地 | 2 | 验证不同真实出口、远程应用、轮换和回退 |
| 外部 AnyTLS 节点 | 1 | 只提供已有连接参数，不安装项目、不开放管理权限 |
| 测试用户 | 至少 2 | 验证身份隔离、共享配额和相互不影响 |

每台机器在开始前记录：

- 测试资产标识和角色，不把地址或凭据写入仓库。
- 系统版本、内核、sing-box、Nfuse、NGINX 和 OpenSSH 版本。
- 当前监听端口、服务状态、防火墙摘要和配置摘要。
- 可执行的快照恢复或卸载方式。
- 测试专属密钥和凭据的销毁方式。

入口、落地和外部节点必须与正式业务隔离。不得复用正式用户密码、SSH 私钥、证书私钥、DNS Token 或 Nfuse 数据。

## 原型结构

### 入口公网层

- 只公开 TCP 443 和经授权的 SSH 管理入口。
- NGINX `ssl_preread` 将已知 SNI 映射到对应的本地 AnyTLS 认证入站。
- 空 SNI、未知 SNI 和被停用路由使用拒绝后端，不能命中默认真实出口。
- 本地认证入站只监听 loopback，每条路由只接受所属用户密码。

### 入口认证和分流层

- sing-box 在入口终止客户端 TLS 和 AnyTLS。
- 认证成功后按当前显式优先级匹配启用中的规则；scope 只限制适用用户。
- 未命中规则时使用该 SNI 对应的默认受管落地。
- 规则可以选择另一台受管落地或现有 AnyTLS 外部节点。
- 出口不可用时拒绝连接，不配置自动 fallback 或 direct。

### 入口计费层

- Nfuse 只绑定 loopback。
- 每个测试用户一个 Nfuse 账户。
- 每个 `(user, egress)` 一个只监听 loopback 的计费端口。
- sing-box 只有认证成功并选择出口后，才向该端口建立第二段加密连接。
- 本地透明中继把加密字节原样送往真实出口。
- 所有能到达远端的受管路径必须经过一个且仅一个计费端口。

### 受管落地

- 每台落地只有稳定的入口到落地 AnyTLS 网关，不创建普通用户入站。
- 网关使用测试专属服务凭据，正式证书验证策略在测试环境中不得被静默跳过。
- 云安全组和主机防火墙只允许入口来源访问网关端口。
- 落地不运行用户配额权威，也不保存用户分流。

### 外部 AnyTLS 节点

- 保持原配置，不安装 landing agent，不改变防火墙或服务。
- 入口使用当前分流已有的 address、port、password、SNI 和证书验证语义连接。
- 外部节点只应看到来自入口的普通 AnyTLS 连接。
- 至少准备一个严格验证证书的出口；如验证旧版 `insecure` 兼容，必须另设独立样本并检查界面持续警告，不能把它计作正式安全证据。

## 证据规则

每个测试用例必须记录：

- 测试用例编号、时间、软件版本和测试资产脱敏标识。
- 操作前后的服务状态、配置摘要、Nfuse 用量和阻断状态。
- 实际出口的脱敏标识，不保存公网地址。
- 预期、实际结果和通过/失败。
- 失败时的回退动作和回退后检查。

证据不得包含用户名、完整 SNI、密码、私钥、SSH 命令行凭据、客户端 URL、真实地址或未脱敏配置。需要关联对象时使用本次测试专用的不可逆摘要。

任何测试只有自动断言或可重复的命令结果，没有“肉眼看起来正常”的结论，才能计为通过。

## 验收矩阵

### A. 认证发生在计费之前

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AUTH-01 | 正确 SNI 与正确密码 | 连接成功，只命中所属用户与实际出口的一个计费端口 |
| AUTH-02 | 正确 SNI 与错误密码 | 入口拒绝；该用户和其他用户 Nfuse 用量与计费端口包计数均不增加 |
| AUTH-03 | 用户 A 密码连接用户 B SNI | 入口拒绝；A、B 用量均不增加，远端没有新连接 |
| AUTH-04 | 空 SNI | 公网层拒绝；没有认证入站、计费端口或远端连接 |
| AUTH-05 | 未知 SNI | 公网层拒绝；没有默认出口或兜底路径 |
| AUTH-06 | 高频错误认证 | 用户用量不增加；入口连接/CPU保护生效且诊断不泄密 |

AUTH-02 和 AUTH-03 使用无其他活动的新测试用户。测试前清零或记录基线，连续执行足以覆盖多个 TLS/AnyTLS 认证尝试，等待 Nfuse 持久化后要求字节值严格等于基线；同时验证目标计费端口没有建立连接。只证明“增量很小”不算通过。

### B. 默认线路和现有分流语义

准备：用户 A 至少有落地 A、落地 B 两条客户端路由；配置两条顺序明确、可确定命中的规则，其中一条指向受管落地 B，另一条指向外部 AnyTLS 节点。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| ROUTE-01 | 连接默认落地 A，访问未命中目标 | 出口为 A |
| ROUTE-02 | 同一连接访问命中受管落地 B 的目标 | 出口为 B，默认 A 不产生该连接 |
| ROUTE-03 | 命中外部 AnyTLS 规则 | 出口为外部节点，节点无需任何配置变化 |
| ROUTE-04 | 调整两条规则的显式顺序 | 重叠目标按新顺序命中，取消调整时配置和服务不变 |
| ROUTE-05 | `scope=user` | 只影响指定用户；另一用户保持自己的默认线路 |
| ROUTE-06 | `scope=all` | 两个用户都按该规则选择出口，但分别计入自己的账户 |
| ROUTE-07 | 同一作用范围、同一规则指向两个出口 | 配置阶段拒绝，运行配置不变 |
| ROUTE-08 | 规则出口不可达 | 命中连接失败，不回退默认落地或 direct |
| ROUTE-09 | 严格验证的外部 AnyTLS 密码或证书错误 | 命中连接失败，不回退；秘密不出现在日志或 argv |
| ROUTE-10 | 迁移旧版 `insecure` 外部出口 | 保持原连接行为，但明确显示持续安全警告；新建出口不默认选择该设置 |

### C. 共享配额和恰好一次计费

| 编号 | 场景 | 通过条件 |
|---|---|---|
| QUOTA-01 | 用户 A 分别通过默认落地 A、规则落地 B 和外部 AnyTLS 产生流量 | 三个计费端口增量汇入同一个 A 账户 |
| QUOTA-02 | 检查单次连接 | 只命中一个 `(A, egress)` 计费端口，其他 A 端口和 B 账户无增量 |
| QUOTA-03 | A 多出口并发下载 | 总用量持续汇总，无明显重复计费或未计费路径 |
| QUOTA-04 | A 达到硬配额 | A 的默认、受管分流和外部 AnyTLS 路径全部停止 |
| QUOTA-05 | A 已阻断时使用 B | B 保持正常，B 用量只记录自己的流量 |
| QUOTA-06 | 缺少或错误计费绑定 | 配置检查拒绝或路径失败关闭，不能直达远端 |
| QUOTA-07 | Nfuse 热重启与整机重启 | 已用量、端口归属和阻断状态保持一致 |

“恰好一次”以连接只穿过一个计费绑定、Nfuse 账户端口映射一致和不存在绕过路径共同证明。不能只根据下载文件大小推断，因为传输加密和协议开销会使计数字节与业务载荷不同。

### D. 受管落地集中管理

| 编号 | 场景 | 通过条件 |
|---|---|---|
| CTRL-01 | 首次注册 | 用户确认固定主机指纹；受限账户和独立密钥安装成功；管理员凭据未保存 |
| CTRL-02 | 普通同步 | forced command 只能应用严格 schema 的目标落地包，不能获得 shell、PTY 或转发 |
| CTRL-03 | 任意命令、任意路径或额外参数 | landing agent 拒绝，系统文件不变 |
| CTRL-04 | 错误 landing_id、过期包、重复 nonce 或旧 revision | 拒绝且不修改当前配置 |
| CTRL-05 | 正常 apply | 快照、语法检查、原子替换、重载和健康检查后返回正确 revision/digest |
| CTRL-06 | 配置语法错误 | apply 失败并保持旧服务可用，入口不开放新路径 |
| CTRL-07 | 重载或健康检查失败 | 自动恢复快照；返回失败和已恢复 revision |
| CTRL-08 | apply 中断 | 下次 reconcile 幂等完成或回退，不产生半生效配置 |
| CTRL-09 | 单台密钥轮换/吊销 | 只影响目标落地，旧密钥不能再次应用 |
| CTRL-10 | SSH 主机指纹变化 | 自动连接停止并提示人工核验，不接受新指纹 |
| CTRL-11 | 落地更新和回滚 | 入口能验证版本、健康状态和回退后的配置摘要 |

受管落地配置中不得出现普通用户、用户密码、分流规则或用户 Nfuse 账户。增加、续期、停用和删除测试用户后，两台落地的期望配置摘要必须保持不变。

### E. 生命周期、重启和恢复

| 编号 | 场景 | 通过条件 |
|---|---|---|
| LIFE-01 | 添加用户 | 只修改入口；所有入口对象准备完成后才公开 SNI |
| LIFE-02 | 停用或到期 | 入口立即关闭全部路由；用量保留；落地无需用户清理 |
| LIFE-03 | 启用或续期 | 入口对象一致后恢复路由，原共享用量语义保持 |
| LIFE-04 | 删除用户 | 关闭路由、移除全部计费绑定和账户后再删状态；落地摘要不变 |
| LIFE-05 | 新增或修改分流 | 只修改入口；受管落地配置摘要不变 |
| LIFE-06 | 入口重启 | 公网映射、认证、分流、配额和 revision 自动恢复 |
| LIFE-07 | 单台落地重启 | 只影响该出口；其他出口和入口管理正常 |
| LIFE-08 | 拓扑或状态损坏 | 停止生成和发布新配置，不覆盖最后一个已验证运行版本 |
| LIFE-09 | 操作中收到 TERM/HUP/INT | 临时明文清理，事务恢复或留下明确可恢复状态 |

### F. 协议、性能和容量基线

| 编号 | 场景 | 通过条件 |
|---|---|---|
| NET-01 | TCP 浏览、下载和长连接 | 三类出口均按规则工作并计费 |
| NET-02 | AnyTLS 支持范围内的 UDP/DNS | 默认和分流路径均有明确成功或受支持边界，不能静默漏计 |
| NET-03 | 入口到落地高 RTT、丢包和断连 | 失败语义明确，无绕过、跨用户或状态损坏 |
| PERF-01 | 双层 AnyTLS 与本地中继开销 | 记录入口 CPU、内存、连接数、吞吐和额外延迟 |
| PERF-02 | 10 用户 × 2 受管落地 × 1 外部出口 | 配置生成、检查、reload 和 Nfuse reconcile 时间可重复记录 |

最小 POC 不据此承诺生产容量。进入 Release 前必须再测试至少 `100 用户 × 3 出口`，并根据结果设定明确上限；没有数据时不直接承诺 1000 用户规模。

### G. 交互界面和角色隔离

| 编号 | 场景 | 通过条件 |
|---|---|---|
| UI-01 | 未部署服务器首次启动 | 只提供单机或入口控制器安装选择；查看和返回不修改环境 |
| UI-02 | 已有 standalone 启动 | 继续显示 v4 用户、分流和系统菜单，不增加入口/落地层级 |
| UI-03 | entry-controller 启动 | 显示入口机、落地机、数据备份与恢复、系统管理四个一级菜单和脱敏状态摘要 |
| UI-04 | 状态摘要部分读取失败 | 对应项目显示未知并允许进入诊断，程序不直接退出 |
| UI-05 | 添加用户并选择多条线路 | 只修改入口，导出每条允许线路的独立客户端节点，落地配置摘要不变 |
| UI-06 | 选择现有 AnyTLS 分流出口 | 位于分流出口管理，不出现在受管落地列表；远端不发生管理操作 |
| UI-07 | 批量同步多个待处理落地 | 逐台快照、应用和检查；一台失败后停止，剩余节点保持待同步 |
| UI-08 | 停用或移除落地 | 先预览受影响线路、分流和待处理操作；取消不修改，确认后失败关闭而不改走其他出口 |
| UI-09 | 普通登录受管落地本地菜单 | 只能查看状态和检查服务，不能添加用户、修改分流或编辑网关 |
| UI-10 | 落地紧急回退 | 独立确认并写入 emergency override；入口不能静默覆盖，必须先显示差异并 reconcile |
| UI-11 | 入口或落地更新 | 两类更新入口明确分开，不能用一次选择同时批量更新全部主机 |
| UI-12 | 任意改变状态的流程 | 显示影响预览和最终验证；取消零修改；失败说明已恢复、待恢复或人工处理状态 |

## 静态和负向门禁

原型或后续实现必须有自动反向测试，至少拒绝：

- 从公网 SNI 映射直接连接远端，绕过入口认证。
- 入口认证成功后直接连接远端，绕过本地计费端口。
- 同一有效连接依次通过两个计费端口。
- 用户 A 的 `(user, egress)` 绑定加入用户 B 的 Nfuse 账户。
- 计费端口监听非 loopback 地址。
- 未知 SNI 指向真实认证入站或出口。
- 分流失败后自动使用 default 或 direct。
- 密码、私钥或 Token 出现在进程 argv、systemd unit、日志或诊断。
- landing agent 接受任意 shell、命令、路径、目标主机 ID 或非递增 revision。
- 用户生命周期修改受管落地的用户列表，因为落地不应存在该列表。

## POC 执行顺序

1. 建立专用测试资产、快照和凭据销毁记录。
2. 只搭建一个入口本地认证入站、一个计费端口和一个受管落地，先完成 AUTH-01/02。
3. 增加第二用户，完成交叉身份和账户隔离负向测试。
4. 增加第二受管落地，完成默认线路、共享配额和故障隔离。
5. 接入不受管的现有 AnyTLS 测试节点，完成分流兼容和证书失败测试。
6. 实现受限 landing agent，完成远程应用、中断和回滚测试。
7. 完成重启、UDP、性能和容量基线。
8. 汇总证据，逐条判定通过、失败或未验证；失败项不得用风险接受代替技术门禁。

每一阶段只有前一阶段全绿才能继续。这样最早暴露“认证后计费链不可行”的根本问题，避免提前开发控制面和菜单。

## 停止条件

出现以下任一结果，POC 立即停止进入实现：

- 任意错误认证使用户 Nfuse 用量增加。
- 任意有效路径绕过计费或重复计费。
- 用户可以借用其他用户 SNI、密码、计费端口或账户。
- 受管落地或新建外部 AnyTLS 只有关闭证书验证才能使用。
- 分流出口失败会自动走默认线路或 direct。
- landing agent 需要通用 root shell、长期保存管理员密码或允许任意命令。
- 中断后无法判断当前生效 revision 或无法恢复旧配置。
- 诊断、日志或进程参数泄露秘密。

停止后保留 v4 `standalone`，清理测试资产，并回到 ADR 重新选择架构；不得退回认证前按 SNI 消耗用户配额的透明 TLS 方案。

## 通过条件

只有以下条件全部满足，后续独立的 POC 执行 Issue 才能关闭，v5 才能进入运行代码实现：

- AUTH、ROUTE、QUOTA、CTRL、LIFE、NET、UI 中所有必测项通过。
- 每个结果都有脱敏、可重复证据。
- 两台受管落地不含用户级配置，外部 AnyTLS 节点没有被修改。
- 入口是用户、分流、计费和落地 revision 的唯一权威。
- 回退演练恢复到测试前状态，测试专属秘密可以完整吊销或销毁。
- 已把失败、未验证和容量边界写入正式记录。
- 项目所有者确认客户端线路选择和分流结果符合预期。

POC 通过后，下一个独立 Issue 只应设计 v5 状态和迁移 schema；不能在一个 PR 中同时实现 schema、证书、入口数据面、远程控制和菜单。
