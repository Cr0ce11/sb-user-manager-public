# 产品方向

## 产品定位

`sb-user-manager` 面向不熟悉 Linux 命令和 sing-box 配置的服务器使用者，通过中文菜单完成用户、流量、分流、升级、诊断和迁移管理。

产品优先级依次为：

1. 不损坏现有服务器和用户数据。
2. 普通用户能够看懂并完成操作。
3. 操作失败、SSH 中断或服务器重启后能够恢复。
4. 默认配置安全且足够好用。
5. 高级能力通过逐层菜单呈现，不增加主流程负担。

## 决策职责

- AI 产品与技术负责人负责理解真实目标、规划日常优先级、定义默认体验、形成技术方案、兼容策略、风险和验收标准。
- Codex 执行代理负责代码实现、测试、文档、Pull Request 和获授权测试环境验证。
- 项目所有者保留最终业务验收、正式环境上线和高风险操作授权。
- GitHub 仓库中的项目文档、Issue、决策记录和 Pull Request 是跨对话传递信息的正式依据。

## 产品约束

- 正式支持环境以 README 声明为准，扩展平台前必须有对应测试。
- 已安装用户的配置、凭据、配额、累计用量和迁移包兼容性不能被静默破坏。
- 危险操作必须先预览、明确确认，并具备备份或回滚路径。
- 面向用户的提示使用清晰中文；不得要求用户理解内部字段或 shell 细节。
- 新功能默认遵循渐进式披露，常用路径保持简短。

## 需求进入开发的条件

一项需求至少应说明：

- 用户要解决的问题。
- 用户在菜单中会看到和执行什么。
- 默认行为与取消路径。
- 不能受影响的现有能力。
- 可验证的完成标准。

技术实现和普通技术取舍由 AI 产品与技术负责人在开发过程中细化。只有产品行为存在实质歧义，或选择会导致数据丢失、权限变化、秘密暴露、外部影响扩大和不可逆操作时，才必须请求项目所有者确认。
