# ADR 0032：操作前的完整环境快照只服务于自动回滚，不提供手工恢复入口

## 状态

已接受。2026-08-21 由项目所有者拍板，关闭 [公开 Issue #207](https://github.com/Cr0ce11/sb-user-manager-public/issues/207)。

## 背景

脚本在七处不可逆或高风险操作之前创建一份「操作前的完整环境快照」：

| 操作 | 函数 |
|---|---|
| 部署或修复环境 | `deploy_environment` |
| sing-box 正式版／测试版通道切换 | `perform_singbox_channel_switch` |
| 换内核到 mihomo | `switch_kernel_to_mihomo` |
| 清理 sing-box 残留 | `cleanup_singbox_leftovers` |
| 完整卸载 | `uninstall_managed_environment` |
| 一致性修复 | `repair_consistency` |
| 从迁移备份恢复 | `restore_migration_backup` |

快照保存在 `/root/sb-user-manager-backups/<时间戳>/`，权限 700，自动保留最近 5 份（[ADR 0003](0003-backup-lifecycle.md)），内容含内核可执行文件、运行配置、systemd 单元、管理配置、用户资料、AnyTLS 证书与 Nfuse 数据库的独立 SQLite 快照，并带 `MANIFEST.sha256` 与符号链接清单。

它的**自动**那一半工作得很好，两条路都经过真机验证：操作中途失败时脚本自己回滚，进程被杀或断电时由下次启动的环境事务恢复完成。

缺的是**事后**那一半。换内核的真机演练确认了这份快照是完整的——在一台已经切成 mihomo、并且已经清理掉 sing-box 残留的机器上把切换前的快照整体恢复回去，机器完整回到了切换前，用户、分流与累计用量都在，`audit` 失败项 0。但这只能通过库模式直接调用 `restore_environment_backup` 做到，**菜单里没有入口**。于是出现这样一种局面：操作成功了、过一阵子才发现不对劲，机器上明明躺着一份操作前的完整快照，使用者却没有办法用它。

## 决定

**不提供手工恢复入口。快照只服务于自动回滚。**

相应地，**任何不可逆操作之前必须先有一份复制到服务器之外的 `.sbm` 加密迁移备份**——那是事后反悔时唯一的退路，不是形式。

## 为什么不做

**恢复整机快照会静静抹掉快照之后的一切。** 快照是某个时间点的整机镜像：恢复它，那之后新增的用户、新加的分流、累计的用量全部回到快照当时的样子。做成一个菜单项，意味着使用者点两下就能造成这种范围的后果，而他在确认提示上看不到自己会丢什么。要让它安全，必须先有一份「这次恢复会丢掉哪些用户、哪些分流、多少用量」的差异预检——那是这项功能里最大的一块工作，而不是把 `restore_environment_backup` 接到菜单上就完事。按本项目的排期原则，能让人轻易造成大范围后果的界面要排在对应护栏之后，不能反过来。

**替代路径是通的，而且更适合这件事。** `.sbm` 加密迁移备份是使用者自己决定何时创建、自己保管、可以复制到服务器之外的东西。它比快照重（要重装一台机器再恢复），但它恢复的是**数据**而不是**整机状态**，不会连带把系统抹回过去，也不会因为放在同一台机器上而与机器一起丢失。

**快照里装着凭据。** 用户资料、AnyTLS 私钥与 Nfuse 数据库都在里面。把它做成一个可以浏览、选择、恢复的界面，等于给凭据多开一条出口；如果再允许恢复到另一台机器，就变成了一条完全没有密码保护的迁移通道——而 `.sbm` 是加密并需要密码的。这条边界不划清就不该开这个口子。

**快照本身也不认得自己是谁。** 清单里只有格式版本、符号链接表和 sha256，没有记录它是哪个操作创建的。要列给人选，还得先给快照补上来源标记，而已经存在于机器上的旧快照补不了。

## 这个取舍换来了什么，又放弃了什么

**换来**：没有多出一个能一键回滚整机、却看不见代价的入口；凭据没有多一条出口；快照的职责保持单一，只被脚本自己使用。

**放弃**：操作成功之后才发现不对时，机器上那份完整快照用不上，只能走「重装一台 + 从 `.sbm` 恢复」这条更重的路；如果当时根本没做 `.sbm` 备份，就没有退路。

这个「如果」正是这个决定的成本所在，因此它不能只写在文档里。

## 配套要求：把「必须先有 .sbm」变成脚本会说的话

文档里的规矩靠人记得，而真需要退路的那一刻，人已经站在确认提示前面了。因此换内核与清理 sing-box 残留这两处确认提示改为：

- 不再说「退路是从切换前的完整环境快照整体恢复」——那句话在没有手工恢复入口的前提下是一句空头承诺。
- 改为当场清点本机的 `.sbm` 加密迁移备份：有几份、最新一份是哪个，并提醒确认它已复制到服务器之外；**一份都没有时明确说出来**，并指出应当先去创建。

脚本不强行阻止操作——项目所有者可能有仓库不知道的服务器外副本。它只保证「没有退路」这件事不会悄悄发生。

## 哪天不再接受这个取舍，退路是什么

出现下列任一情况时重新评估：

- 真的发生了一次「操作成功、事后反悔、当时没有 `.sbm`」，说明上面那条配套要求没有兜住。
- 出现第二个像换内核这样「`.sbm` 是唯一退路」的不可逆操作，快照与 `.sbm` 的分工需要重新划。
- 审计侧已经能算出「两个状态之间差了哪些用户、哪些分流、多少用量」——那时差异预检不再是这项功能的主要成本，做入口的代价大幅下降。

真要做的时候，路径是清楚的：在「数据备份与恢复」里加一项「从操作前快照恢复」，列出现有快照，选中后先做只读预检**并当面列出会丢失的内容**，确认后再恢复；恢复本身仍包在环境事务里，并在动手前再创建一次快照。只允许恢复到本机，不开跨机——跨机迁移是 `.sbm` 的职责，它有密码。

## 后续（2026-08-22）：三处快照点随 sing-box 线归档消失

sing-box 线归档时撤除了 sing-box 通道切换、换内核到 mihomo、清理 sing-box 残留三项（[公开 Issue #256](https://github.com/Cr0ce11/sb-user-manager-public/issues/256)）。上表七处快照点因此只剩四处：部署或修复环境、完整卸载、一致性修复、从迁移备份恢复。

**本 ADR 的决定不变**，但「配套要求」那一节的实现随之消失：`print_offsite_recovery_status` 的两个调用点就是被撤除的那两处确认提示，函数因而成了孤儿，一并删除（留着一段谁都调不到的代码，迟早有人以为它还在起作用）。

**这条要求本身没有作废。** 剩下四处里唯一「事后反悔就没退路」的是完整卸载，而它有自己更重的一套：卸载前列出即将删除与保留的内容，并直接提供「创建新的加密迁移备份后卸载」这一选项，还会做完整性检查。就这一处而言，覆盖比原来那句提示更强。

**再添一个不可逆操作时，必须重新落实这一条**——不能默认它还在。`tests/test-static.sh` 里现在钉着「`print_offsite_recovery_status` 不得作为死代码留下」，那条断言的存在本身就是这段历史的路标；重新需要它时把函数写回来，并同时接上调用点。

## 后续（2026-08-23）：这条要求走过一个完整来回，形状与预期一致

「搬迁管理器数据目录」（[公开 Issue #276](https://github.com/Cr0ce11/sb-user-manager-public/issues/276)）就是上面预告的「再添一个不可逆操作」——它在校验通过后删掉老位置的用户资料、内部备份与 AnyTLS 证书。当时按本节要求把 `print_offsite_recovery_status` 写了回来并接上唯一的调用点（搬迁的确认提示），`tests/test-static.sh` 的断言随之从「不得存在」改成「必须正好有一个调用点」。

那个入口是一次性的，正式机与测试机全部搬完之后按计划整段撤除（[公开 Issue #283](https://github.com/Cr0ce11/sb-user-manager-public/issues/283)），这个函数因此**第二次**成为孤儿，随之第二次删除，断言也改回「不得存在」。快照点回到四处：部署或修复环境、完整卸载、一致性修复、从迁移备份恢复。

**记下这个来回，是因为它证明这套安排是可用的**：预告写在 ADR 里、断言钉在门禁里，新增不可逆操作的那一版真的把它捡了回来，撤除的那一版又真的把它清干净了，中间没有人靠记性。下一个不可逆操作是改名迁移（[公开 Issue #281](https://github.com/Cr0ce11/sb-user-manager-public/issues/281) 第 3 步的磁盘改名），届时同样要把函数写回来并同时接上调用点。

**一条不随入口回退的东西**：`is_environment_recovery_path` 里 `/etc/sb-user-manager` 那条字面量。恢复记录是给下一次运行的进程读的，它的 `MANAGER_DATA_DIR` 来自当时读到的管理配置；只按当前取值匹配，会让中途崩溃的机器被判成「记录里是不受管路径」而拒绝恢复。那条字面量钉的是本项目固定的数据目录名，与一次性入口无关。
