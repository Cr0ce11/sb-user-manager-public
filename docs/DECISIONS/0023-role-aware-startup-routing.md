# ADR 0023：角色感知启动分发与首次入口安装

- 状态：已接受，专用服务器验收通过
- 日期：2026-08-08
- 关联：[ADR 0005](0005-entry-authenticated-multi-egress-controller.md)、[ADR 0021](0021-entry-controller-role-provisioning.md)、[ADR 0022](0022-read-only-manager-role-detection.md)、[Issue #234](https://github.com/DTB201/sb-user-manager/issues/234)

## 背景

管理器过去总是假定当前机器是 standalone，并在识别角色前执行 v4 环境恢复、备份权限整理和状态迁移。入口控制器或受管落地若进入该流程，会把只属于 standalone 的菜单与副作用带到错误角色。全新机器也会先看到完整 v4 菜单，而不是明确选择部署角色。

## 决定

普通启动先通过 ADR 0022 的唯一只读入口识别角色，再分发到互相隔离的界面：

- `undeployed` 只显示“安装为单机节点”“安装为入口控制器”和退出。显示、取消或 EOF 不写系统；单机安装继续调用既有安装入口，入口安装在影响说明和二次确认后只调用 ADR 0021 的唯一编排入口。
- `standalone` 保持原 v4 恢复、历史权限收紧、启动副本同步、迁移顺序和三板块菜单。环境恢复后必须再次识别，只有仍为 standalone 才继续。
- `entry-controller` 显示入口机、落地机、数据备份与恢复、系统管理四个一级板块以及只读脱敏摘要。尚未独立验收的业务动作只显示未开放提示，不回落到 standalone。
- `landing` 只显示受入口管理的只读界面骨架。紧急恢复、撤销管理和普通业务编辑均不在本阶段开放。
- `unknown` 只按稳定分类显示不含路径、地址、用户数据或秘密的中文说明，并失败关闭。

内部到期任务同样先识别角色，只有 standalone 可以执行。入口和落地不执行 v4 环境恢复、用户迁移、备份保留迁移或共享预置迁移。

## 旧环境恢复日志

v4 部署在中断后可能只留下环境恢复日志和不完整文件足迹。启动分发不能把该现场误认为可直接创建入口角色。固定恢复日志只有在以下条件全部满足时才沿用既有恢复函数：

1. 日志是当前 root 所有、组和其他用户不可访问的普通文件，不能是符号链接；
2. 当前角色为 standalone、undeployed，或只读识别结果为 standalone 不完整/外部文件足迹；
3. 恢复完成后日志确实消失，并重新执行完整角色识别。

若已经识别为 entry-controller 或 landing，任何 v4 环境恢复日志都视为角色冲突，不自动恢复或删除。混合角色、非法身份和不安全运行路径同样不能借恢复日志绕过失败关闭。

## 不包含

- 不开放添加落地、root 引导、远程 apply、同步或回滚。
- 不实现入口 AnyTLS 数据面、认证后计费、共享配额或多线路导出。
- 不把 v4 迁移备份直接用于尚未定义 schema 的 v5 控制器数据。
- 不安装或修改落地机，也不发布正式版本。

## 验收与回退

自动测试覆盖四角色、失败分类、取消/EOF、入口安装成功和失败、恢复日志冲突、standalone 顺序与内部任务隔离。合并前还必须在专用 Debian 12 x86_64 入口和落地测试机验证首次安装、APT 失败重试、幂等启动、角色隔离、重启和回退。

2026-08-08 已在两台干净的专用 Debian 12 x86_64 测试机完成验收，使用的单脚本摘要为 `eaba7bc0322cb1bb527ca7d4edf8190b184cf0f8c0b9095cd34f21e194cfb15f`：未部署菜单在确认前不写系统；入口安装在隔离网络中遇到 APT 失败后未留下角色状态或半安装包，恢复网络后重试成功；重复启动和真实重启后均只进入入口菜单，空控制器状态摘要与权限保持不变，单机内部任务被拒绝；落地测试机全程保持未部署且没有新增依赖、服务或端口。最后已精确删除空控制器状态和两台机器上的测试脚本，确认项目路径恢复为不存在、包管理器健康且仅 SSH 监听；入口安装的 Debian 官方共享依赖按既定边界保留。

代码回退为撤销本模块和 main 分发并重新生成单脚本。入口测试机回退优先恢复测试快照；若只创建了空控制器状态，可在确认没有 landings 和秘密后精确移除本次新增状态。Debian 官方共享依赖不盲目卸载。落地机在本阶段只读，不应产生项目变更。
