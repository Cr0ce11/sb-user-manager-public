# ADR 0021：入口控制器角色安装与修复编排

- 状态：已接受，编排模块尚未接入运行流程
- 日期：2026-08-08
- 关联：[ADR 0019](0019-entry-controller-role-initialization.md)、[ADR 0020](0020-entry-controller-dependency-repair.md)、[Issue #230](https://github.com/DTB201/sb-user-manager/issues/230)

## 背景

入口角色初始化和固定依赖修复已经分别具备失败关闭边界，但未来交互层若自行决定调用顺序，可能先在 standalone、部分部署或外部 sing-box 环境执行 APT，之后才由初始化门禁发现角色冲突。入口安装需要一个唯一编排入口，把“目标确认在前、系统修改在后”固定为不可绕过的顺序。

## 决定

新增 dormant 的 `provision_entry_controller_role`，只接受零参数。真实运行时先把 `PATH` 固定为系统目录、区域设置固定为 `C`，并清空会影响子进程加载、目录解析、Python 或 OpenSSL 的继承变量。函数不读取包名、路径或命令形式的外部输入。

调用顺序固定为：

1. 只读验证 root、Debian 12 x86_64 和固定控制器路径。
2. 若存在控制器状态，必须完整验证状态、秘密目录和可选锁文件；若尚无状态，必须确认角色残留安全且 v4 管理、部分部署和外部核心足迹均为空。
3. 目标确认通过后才调用 ADR 0020 的固定依赖修复。可疑依赖、APT 失败或安装后依赖复检失败直接保留原结果并停止。
4. 依赖就绪后调用 ADR 0019 的幂等初始化。该调用重新验证全部依赖、角色残留和环境足迹，因此 APT 期间新出现的冲突不能被提交为入口角色。
5. 全新初始化返回 `entry_role_initialized`；合法既有入口补齐依赖返回 `entry_role_repaired`；全部已经就绪返回 `entry_role_ready`。失败继续使用底层稳定状态，只有不可能的内部成功组合才返回 `provision_failed`。

合法既有入口的控制器状态是角色身份依据；编排不得重写状态、清空 landings、降低 revision 或修改秘密。全新环境的 APT 成功但角色初始化失败时，官方依赖可以已经安装；再次调用必须从只读目标确认重新开始并幂等收敛，不尝试卸载系统包。

## 引导下限

目标确认本身需要少量受信任系统工具。特别是合法既有入口必须在 APT 前解析并验证控制器状态，因此若 `/usr/bin/jq` 本身已经缺失或不可信，自动编排会失败关闭并要求先人工恢复系统解析工具，不能为了自动修复而在未确认角色身份时放宽状态校验。全新环境没有既有状态，可以由固定 APT 路径补齐 jq 等完整依赖。

## 不包含

- 不接入菜单、启动、在线更新、定时任务或恢复钩子。
- 不安装入口数据面、NGINX、sing-box、Nfuse 或落地侧组件。
- 不建立用户线路、共享配额、外部 AnyTLS 出口或迁移格式。
- 不把 CI 测试等同于真实服务器上的包锁、网络源、重启和断电验收。

## 回退

在接入菜单前，撤销编排函数、定向测试与本文档并重新生成单脚本即可回退。已经由 APT 安装或重装的 Debian 官方依赖沿用 ADR 0020 的加法型边界，不自动卸载；控制器状态只能由通过最终门禁的初始化创建。
