# 0004：完整卸载保留迁移备份

- 状态：已接受
- 日期：2026-07-25
- 关联：[Issue #140](https://github.com/DTB201/sb-user-manager/issues/140)

## 背景

项目已经能够安全安装、更新和在失败时回滚，但成功部署后没有面向普通用户的完整卸载入口。手工停止服务和删除文件容易遗漏 systemd 单元、运行数据、证书或快捷入口，也可能误删仍有迁移价值的用户资料。

## 决定

- 安装、修复和完整卸载归入同一个“部署与卸载”菜单，不增加同类一级菜单。
- 完整卸载删除项目实际运行环境、项目专属状态和内部回滚材料。
- 用户主动创建或导入的 `.sbm` 加密迁移包不属于临时运行材料，完整卸载后继续保留。
- Debian 共用工具不自动卸载，无法可靠证明属于本项目的 root 文件不删除。
- 默认引导用户创建新的迁移备份；用户可以明确选择不创建，但必须经过独立确认并始终可以返回。
- 卸载本身使用完整环境快照和持久化事务保护。失败或受控中断恢复卸载前环境；只有全部成功后才清理临时回滚点。
- 历史接管环境不承诺恢复成接管前状态。若旧状态已经不在现有备份中，界面必须如实说明，不能猜测还原。

## 结果

- 用户能够通过一个明确流程撤销部署，不需要理解 systemd、目录和程序文件。
- 误触、SSH 回连和中途失败不会直接造成不可恢复的数据丢失。
- 卸载后的服务器不再运行本项目服务，同时仍保留可迁移到新服务器的加密业务数据。
