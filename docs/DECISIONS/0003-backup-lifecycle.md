# 0003：备份按用途采用不同保留策略

- 状态：已接受
- 日期：2026-07-24
- 关联：[Issue #133](https://github.com/DTB201/sb-user-manager/issues/133)

## 背景

项目同时存在用户主动创建的跨服务器迁移包、安装或更新前的完整环境快照、日常用户和分流操作前的内部事务备份，以及迁移恢复记录。旧实现只提供迁移包和完整快照的手动清理，内部事务备份会长期累积；完整快照还会再次复制这些历史事务文件。

## 决定

- `.sbm` 迁移包属于用户数据，不在后台自动删除。
- 完整环境快照自动保留最近 5 份有效快照。
- 内部事务备份兼容旧版和新版完整文件组，自动保留最近 10 组。
- 迁移恢复记录自动保留最近 20 份有效记录。
- 当前未完成事务引用的备份始终额外保留。
- 自动整理只在创建、业务操作或恢复已经成功后执行；整理失败不改变已经成功的业务结果。
- 删除前重新检查备份结构与完整性。残缺、损坏、名称异常和符号链接保留现场，不进行猜测删除。
- 完整环境快照不再重复携带独立管理的 `/etc/sing-box/backups/` 历史事务文件。
- 查看界面使用快速结构识别统计数量和空间；完整校验只在创建、恢复、验收或实际删除前执行，避免历史快照较多时再次拖慢交互。

## 结果

- 日常使用不需要人工维护内部备份，磁盘占用有明确上限。
- 用户主动创建的迁移包不会因后台策略意外丢失。
- 中断恢复安全边界、迁移包格式、状态 schema、sing-box 和 Nfuse 行为保持不变。
- 第一次运行自动整理的操作可能需要校验较多旧快照；完成后只保留少量新格式快照，后续开销显著降低。
