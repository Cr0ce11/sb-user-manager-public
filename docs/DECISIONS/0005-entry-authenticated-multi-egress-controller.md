# 0005：入口认证后的多出口集中管理

- 状态：已接受，尚未实现
- 日期：2026-08-07
- 关联：[Issue #197](https://github.com/DTB201/sb-user-manager/issues/197)

## 背景

项目现有 v4 版本是单机管理器：用户认证、流量配额、分流和出口都由同一台服务器处理。候选的多落地方案曾计划让入口 NGINX 透明转发客户端 TLS，并在落地完成 AnyTLS 认证。该方案可以用入口 Nfuse 汇总多个落地的流量，但本地计费发生在认证之前；只要某条 SNI 被观察或泄露，无效认证流量就可能消耗该 SNI 所属用户的配额。

项目所有者已经确认以下产品边界：

- 接受入口机作为第一版单点。
- 接受入口机成为可信 AnyTLS 终止和认证节点。
- 用户配额只能统计认证成功后的流量。
- 日常用户、分流和多落地操作全部从入口机完成。
- 交互界面区分入口机管理和落地机管理。
- 现有 AnyTLS 节点必须能继续作为分流出口，不能要求远端安装本项目或提供 SSH。

本决定取代“入口透明 TLS、落地认证、认证前计费”的候选设计。它不改变已发布 v4 的运行行为；实现必须作为后续 v5 主题逐项完成。

## 决定

### 部署模式

保留以下互斥模式：

- `standalone`：保持 v4 的单机行为、菜单、状态和迁移兼容。
- `entry-controller`：统一入口，是用户、配额、分流、拓扑和期望配置的唯一权威。
- `landing`：受管落地，只提供稳定出口网关和受限配置应用能力。

第一版不让同一实例同时承担 `standalone` 和 `entry-controller`，也不实现多入口共享配额或入口高可用。

### 数据路径

客户端可见路径为：

```text
客户端
  -> 入口公网 TCP 443
  -> NGINX 按 SNI 转到入口本地认证入站
  -> 入口 sing-box 终止 TLS 并验证该路由所属用户的 AnyTLS 密码
  -> 按现有分流顺序选择实际出口
  -> 该用户与实际出口对应的本地计费端口
  -> 入口 Nfuse
  -> 第二段加密连接
  -> 受管落地或现有 AnyTLS 外部节点
  -> 互联网
```

公网 NGINX 只负责 SNI 到本地认证入站的失败关闭映射，不负责用户认证。每条客户端路由对应一个不可预测、不可复用且不包含用户名的 SNI；对应的本地认证入站只接受该用户密码。使用用户 A 密码连接用户 B 的 SNI，必须在入口被拒绝。

入口 sing-box 只在认证成功后建立出口连接。出口的加密字节先连接 `127.0.0.1:<meter_port>`，再由只监听 loopback 的透明 TCP 中继送到真实远端。Nfuse 绑定 loopback，并通过这个本地端口统计认证后的双向流量。远端仍然收到正常的 AnyTLS TLS 握手、SNI 和密码，不感知本地计费中继。

### 计费模型

每个用户只有一个 Nfuse 账户。系统为每个实际使用的 `(user_id, egress_id)` 分配一个本地计费端口；相同用户访问同一出口时复用该绑定，不因客户端默认路由不同而重复分配。该用户所有绑定都属于同一个 Nfuse 账户。

必须保持：

- 无效 TLS、错误密码和 AnyTLS 认证失败不会建立出口连接，因此不会进入用户计费端口。
- 默认落地、规则指定落地和外部 AnyTLS 出口都经过同一套认证后计费链。
- 一次有效连接只能经过一个计费端口，不能重复计费。
- 任一受管运行路径不能证明具有正确计费绑定时，配置拒绝生效。
- 配额耗尽后，该用户的全部出口同时受阻，其他用户不受影响。

入口仍需使用连接数、握手超时和来源速率限制抵御资源消耗攻击；这类攻击可以消耗入口 CPU 和连接资源，但不能消耗用户配额。

### 默认线路和分流

客户端 SNI 选择一条默认落地线路。入口认证完成后，分流规则可以覆盖该默认出口。

规则执行继续保持 v4 的产品语义：

- 启用中的分流按照用户手动设置的统一优先级依次匹配。
- `scope=all` 适用于全部用户，`scope=user` 只适用于指定用户；作用范围不自动改变规则优先级。
- 现有的重叠关系校验继续生效，不能让同一作用范围内的同一规则同时指向两个不同出口。
- 所有分流均未命中时，才使用客户端 SNI 所选择的默认落地。
- 指定出口不可用时失败关闭，第一版不静默切换到其他地区、默认线路或直连。

出口分为两类：

1. `managed_landing`：由入口注册、配置、检查、更新和回滚的受管落地。
2. `external_anytls`：现有 AnyTLS 节点，只保存并使用现有的服务器地址、端口、密码、SNI 和证书验证设置；远端不安装本项目、不提供 SSH，也不会出现在落地机管理菜单。

v4 的 AnyTLS 出口预置应能无损迁移为 `external_anytls`，包括现有 `insecure` 取值，迁移不能静默改变正在使用的连接行为。新建外部 AnyTLS 出口默认并推荐严格验证证书；迁移来的跳过验证出口必须明确标为“旧版不安全出口”，每次编辑时显示中间人攻击风险，不能被描述为安全或生产就绪。受管落地不提供该兼容例外。

Shadowsocks 和 SS2022 + ShadowTLS 在 `standalone` 中保持不变；在 `entry-controller` 中只有通过同样的认证后、恰好一次计费以及 TCP/UDP 验证后才能启用，不能因兼容名义绕过安全门禁。

### 受管落地

受管落地只运行稳定的入口到落地 AnyTLS 网关，不保存普通用户、用户配额、用户分流或客户端 SNI。入口使用每台落地独立的服务凭据建立第二段 AnyTLS 连接，落地防火墙只允许入口来源访问网关端口。

因此以下操作只修改入口：

- 添加、续期、停用、启用和删除用户。
- 修改用户配额、到期时间和用量。
- 新增、修改、排序、停用和删除分流。
- 新增或修改外部 AnyTLS 出口。
- 修改用户默认线路和导出客户端配置。

只有以下基础设施操作需要修改落地：

- 首次注册或初始化落地。
- 修改落地网关、证书、防火墙或服务配置。
- 轮换入口到落地服务凭据。
- 更新、修复、停用、移除或回滚落地。

这使用户生命周期不依赖跨主机事务。单台落地故障只影响选择该出口的连接，入口用户状态和共享配额仍保持权威。

### 入口到落地的配置应用

入口使用 OpenSSH 连接受管落地，但不能获得长期的通用 root shell：

- 每台落地使用独立 Ed25519 管理密钥，权限为 root-only，可单独轮换或吊销。
- 首次注册必须固定落地 SSH 主机指纹；后续不接受自动变化。
- 落地建立专用低权限账户，不允许交互 shell、PTY、代理或端口转发。
- `authorized_keys` 使用 `restrict,command="..."` 强制进入 root 拥有的固定 landing agent。
- sudo 仅允许无参数调用一个固定 apply helper，不能执行任意命令或读写任意路径。
- 入口通过 stdin 发送严格 schema 的期望状态包，秘密不进入 argv。
- 状态包包含 `landing_id`、schema、递增 revision、有效期、nonce 和内容摘要。
- SSH 强制密钥完成入口授权；revision、有效期和 nonce 防止旧包重放，摘要防止内容损坏。第一版不额外引入第二套签名密钥。
- 落地先加锁和快照，再渲染允许范围内的配置，执行语法检查、原子替换、重载和健康检查；失败恢复快照。
- 落地只返回脱敏结果、`applied_revision` 和配置摘要，不返回秘密。
- 入口保存 `desired_revision` 与 `applied_revision`，中断后执行幂等 reconcile。
- 新落地路径最后才在入口开放；prepare/apply/health 任一步失败时保持失败关闭。

首次引导可以由入口发起一次交互式管理员 SSH 会话。管理员密码只能由 OpenSSH 直接从终端读取，不保存、不传入 argv；完成受限账户和密钥安装后，日常管理只使用受限通道。若无法验证主机指纹或受限通道，注册必须取消且不能开放数据路径。

### 管理界面

程序启动时根据已保存角色自动显示对应界面，不要求用户每次重新选择模式：

- 尚未部署时只提供“安装为单机节点”或“安装为入口控制器”，选择前不修改环境。
- `standalone` 继续显示 v4 的“用户管理、分流管理、系统管理”，不增加菜单层级。
- `entry-controller` 显示新的集中管理界面。
- `landing` 本地只显示只读状态和紧急恢复，不提供普通业务编辑。

`entry-controller` 主菜单顶部显示入口状态、用户数、正常落地数、待同步数和配额异常数；不能读取的项目显示“未知”，不能因为摘要失败退出程序。一级菜单固定为：

```text
1. 入口机管理
2. 落地机管理
3. 数据备份与恢复
4. 系统管理
0. 退出
```

入口机管理包含：

```text
入口机管理
  - 用户与共享配额
    - 添加、查看和编辑用户
    - 停用、启用和续期
    - 调整流量和删除用户
  - 用户线路与配置导出
    - 设置用户可用落地
    - 增加或移除线路
    - 查看线路状态
    - 导出全部客户端节点
  - 分流管理
    - 查看、验证、新增、编辑和调整顺序
    - 停用、启用和删除
    - 预置规则管理
    - 分流出口管理
      - 选择受管落地机
      - 添加现有 AnyTLS 节点
      - 经过独立门禁的高级兼容出口
  - 公网入口与证书
    - 公网 443、客户端域名、SNI 和证书
    - 连接数、握手超时和来源速率保护
  - 入口服务检查
    - sing-box、NGINX 和 Nfuse
    - 用户、计费与运行配置一致性
    - 入口故障报告
```

添加用户时可以选择允许使用的健康落地，并为每条线路生成独立客户端节点；增加、续期、停用、删除用户和修改分流只修改入口，不能触发落地用户配置或落地服务重载。

落地机管理包含：

```text
落地机管理
  - 查看全部落地机
  - 添加并初始化落地机
  - 检查全部落地机（只读）
  - 同步全部待处理落地机（逐台执行）
  - 查看中断或失败任务
  - 选择一台落地机
    - 查看状态和当前版本
    - 测试真实出口
    - 同步或修复配置
    - 更新运行环境
    - 轮换内部凭据
    - 恢复上一个版本
    - 停用落地机
    - 移除落地机
```

批量同步必须逐台执行“快照、应用、检查”，一台失败后立即停止，未处理的落地保持待同步；第一版不提供全部落地同时更新或并行写入。停用或移除前必须预览受影响的用户线路、分流规则和待处理操作，并说明这些路径将失败关闭而不是自动改走其他地区或直连。

外部 AnyTLS 节点位于“入口机管理 → 分流管理 → 分流出口管理”，只提供添加、查看、测试、编辑、关联、停用和删除。它不出现在落地机管理，因为入口没有管理远端服务器的权限。旧版跳过证书验证的节点必须持续显示不安全标记。

数据备份与恢复延续 v4 的创建、导入、查看、单份/批量检查、恢复预览、恢复记录和清理操作。v5 恢复预览额外显示落地逻辑映射、外部 AnyTLS 出口和会失效或重新生成的客户端线路。

系统管理包含全局运行状态、检查与故障报告、管理器更新、sing-box 版本管理、入口部署或修复以及完整卸载。落地的软件更新和回滚只出现在落地机管理，不能与入口更新混为同一动作。

受管落地本地界面固定为：

```text
本机由入口控制器管理

1. 查看只读状态
2. 查看当前配置版本
3. 检查服务
4. 紧急恢复上一个版本
5. 撤销入口管理（危险操作）
0. 退出
```

落地本地不能添加用户、修改分流或编辑网关。紧急回退或撤销管理必须独立确认，并写入 `emergency_override` 状态；入口之后不能静默覆盖，必须先显示差异并完成明确 reconcile，防止形成第二个事实源。

所有会改变状态的入口操作统一遵循“影响预览、确认、快照、应用、验证、结果”六步；取消必须不产生修改，失败必须显示已经自动恢复、仍待恢复或需要人工处理，不能只显示远程命令错误。

### 状态和秘密边界

后续 schema 必须显式区分：

- 客户端路由：`route_id`、用户、随机 SNI、本地认证入站和默认出口。
- 出口：受管落地或外部 AnyTLS 预置。
- 计费绑定：用户、出口、本地计费端口和 Nfuse 账户。
- 受管落地：地址、网关参数、SSH 主机指纹、期望 revision 和已应用 revision。

外部 AnyTLS 凭据与现有分流一样属于加密迁移数据。SSH 私钥、落地 TLS 私钥、DNS Token、主机地址映射和本地落地快照不进入普通用户迁移包。所有本地秘密文件必须是 root 拥有的普通文件、权限 600，并拒绝符号链接。

状态格式、迁移包和运行配置的具体 schema 不在本 ADR 中确定，必须在后续独立 Issue 中设计、验证升级和回退。

## 安全不变量

1. 认证失败流量不得进入用户 Nfuse 账户。
2. 任何有效用户流量都必须且只能经过一次正确用户的计费绑定。
3. 同一用户全部计费端口属于同一个 Nfuse 账户。
4. 用户 A 的密码不能通过用户 B 的 SNI，也不能增加或绕过任何一方配额。
5. 未知和空 SNI 失败关闭，SNI 不含用户名并且不被其他路由复用。
6. 计费端口只监听 loopback，不能被公网或落地直接访问。
7. 落地或外部出口故障不自动绕到未授权出口。
8. 正式入口、受管落地和新建外部 AnyTLS 出口严格验证证书；旧版外部出口的跳过验证设置只能显式兼容并持续警告，不能静默扩散。
9. 密码、私钥、令牌和完整客户端 URL不进入 argv、日志、诊断或 Git。
10. 入口是唯一期望状态源；落地不能独立修改业务对象。
11. 远程应用必须最小权限、固定主机身份、幂等、可恢复并失败关闭。
12. `standalone` 默认行为不变，不能静默转换已有服务器或用户。
13. 没有专用测试环境证据前不能称为生产就绪。
14. 没有项目所有者单独授权时不能登录或修改正式服务器。

## 结果

- 认证前的恶意或错误流量不再消耗用户配额。
- 用户、配额和分流操作成为入口本地事务，不再要求每次同步全部落地。
- 受管落地配置规模与用户数量解耦，增加用户不会重载落地服务。
- 现有 AnyTLS 节点可以继续作为分流出口，且同样受共享配额约束。
- 入口持有客户端认证信息并处理解密后的代理请求，信任范围和被攻破后的影响扩大。
- 客户端到入口和入口到出口是两段独立加密连接，不再是客户端到落地的端到端 AnyTLS。
- 入口增加 TLS 终止、规则处理和第二段加密的 CPU、内存与连接开销，正式容量上限必须由实测决定。

## 未决定事项

以下内容留给后续独立 Issue，不得在实现时临时猜测：

- v5 状态和迁移包的最终 schema。
- 正式域名、证书签发和自动续期方案。
- entry-controller 中 Shadowsocks 与 SS2022 + ShadowTLS 的 UDP 计费实现。
- 支持的用户数、出口数和本地端口容量上限。
- 入口高可用、多入口共享配额和 IPv6-only 支持。

## 回退

本 ADR 只记录未来架构，不改变运行环境。任何后续原型必须使用专用测试资产，并能通过停止原型服务、恢复测试前快照和删除测试专属密钥完整回退。

若 POC 无法证明认证失败零计费、有效流量恰好计费一次、外部 AnyTLS 兼容或受限远程应用可恢复，则停止 v5 实现，继续维护 `standalone`，不得退回认证前按 SNI 计费的透明 TLS 方案。
