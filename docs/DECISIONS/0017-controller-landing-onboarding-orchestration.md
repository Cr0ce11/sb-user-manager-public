# ADR 0017：单落地初始化的分阶段编排与保守回退

- 状态：已接受，编排核心尚未接入角色路由、菜单或服务器
- 日期：2026-08-08
- 关联：[ADR 0013](0013-controller-pinned-landing-transport.md)、[ADR 0014](0014-controller-landing-registration.md)、[ADR 0015](0015-entry-initiated-landing-root-bootstrap.md)、[ADR 0016](0016-controller-landing-credential-initialization.md)、[Issue #222](https://github.com/DTB201/sb-user-manager/issues/222)

## 背景

入口已经分别具备固定主机指纹传输、受限通道登记、一次性 root 引导和每落地独立凭据初始化，但这些操作跨越入口文件系统、入口控制器状态和远端落地，无法使用一个本地事务原子提交。菜单若自行拼接调用并在任意失败时统一“全部删除”，可能删除恢复所需凭据、撤销已经登记的落地，或在登记结果不明时破坏实际已经建立的通道。

项目已经建立 standalone、entry-controller 和 landing 的持久角色路由骨架，但尚未开放新增落地业务菜单。本决定固定未来“添加并初始化落地机”交互所调用的低层编排核心，不把 dormant v5 功能暴露给现有 v4 菜单；[ADR 0027](0027-readiness-gated-landing-onboarding.md) 在其外层加入秘密生成前 readiness 门禁。

## 决定

### 修改前门禁

编排首先验证可信的 `entry-controller` 状态、全部字段、公开入口 IPv4、SSH 与网关端口不冲突，以及落地 ID和“地址 + SSH 端口”未登记。随后只读发现远端 Ed25519 主机指纹，并要求用户明确确认。输入错误、状态错误、发现失败或拒绝指纹时不生成凭据、不登录 root、不写控制器状态，也不下发配置。

低层入口确认指纹后固定执行“凭据 → 一次性 root 引导 → 原子登记 → 首次 apply”。ADR 0027 的统一入口先完成 readiness，再把同一已确认指纹作为当前调用栈内参数交给本编排，因此不会重复提示；各远程阶段仍会重新固定同一主机身份。完整 SNI 只作为 Bash 函数参数传入既有凭据模块，不新增外部进程 argv、日志或普通输出。

### 失败收敛

编排公开稳定的最终阶段、已确认指纹、远端回退结果和本地凭据结果，供后续中文界面给出真实结论：

| 失败位置 | 处理 |
|---|---|
| 凭据初始化 | 只尝试清理由本次新建且仍未登记的凭据；预先存在的恢复材料保留 |
| root 引导且远端已回退 | 清理本次新凭据，返回“已回退” |
| root 引导但远端回退失败 | 保留凭据和 bootstrap 信息，返回“需要恢复” |
| 登记调用失败且可证明未登记 | 使用原 bootstrap ID 精确回退远端；成功后才清理本次新凭据 |
| 登记结果无法证明 | 不猜测、不回退、不删除，保留全部恢复材料 |
| 已登记但首次 apply 失败 | 保留登记、受限通道和凭据，返回“已登记、待同步” |

登记函数即使返回失败，编排仍重新读取可信控制器状态；若目标已经原子登记，则继续首次 apply，避免把“提交成功但调用者未收到成功”误判为未登记。若状态本身无法验证，则禁止远端回退，因为不能排除控制器已经把该落地作为事实源。

### 材料归属

编排在凭据初始化前记录该落地是否已有任何固定路径材料。只有本次从空路径开始创建、远端已完成精确回退且控制器仍证明未登记时，才调用 ADR 0016 的严格清理函数。预先存在的有效或待人工检查材料一律保留，避免一次重试销毁之前操作的恢复能力。

## 暂不包含

本决定不创建角色、不安装系统依赖、不改变现有主菜单、不连接真实服务器、不修改入口数据面，也不提供批量落地操作。输入收集、入口角色安装、菜单路由和面向用户的阶段提示必须在后续独立 Issue 中实现并复用本编排结果，不能复制一套不同的失败语义。

跨 `SIGKILL` 与断电的阶段、bootstrap ID、精确目标和保守恢复入口已由 [ADR 0018](0018-controller-landing-onboarding-durable-journal.md) 持久化实现。编排及恢复仍保持 dormant，当前没有菜单或服务器路径会触发；任何交互启用都必须复用该日志和恢复语义，不能退回仅依赖进程内变量的实现。

## 回退

撤销 onboarding 模块、测试和本文档并重新生成单脚本即可回退代码。能力保持 dormant，因此不会留下 v4 菜单或线上数据迁移。若未来调用者在远端回退失败或登记状态不明后中止，必须保留凭据并从明确的恢复入口继续，不能用代码回退代替远端收敛。
