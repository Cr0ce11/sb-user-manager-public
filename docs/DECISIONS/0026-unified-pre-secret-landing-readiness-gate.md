# ADR 0026：统一的落地秘密生成前准备门禁

- 状态：已接受并实现，保持 dormant
- 日期：2026-08-09
- 关联：[ADR 0018](0018-controller-landing-onboarding-durable-journal.md)、[ADR 0024](0024-entry-initiated-landing-dependency-preparation.md)、[ADR 0025](0025-entry-initiated-landing-singbox-runtime-preparation.md)、[Issue #240](https://github.com/DTB201/sb-user-manager/issues/240)

## 背景

ADR 0024 与 ADR 0025 分别提供了落地系统依赖准备和 sing-box 运行时准备。两者都能独立发现、人工确认并在连接前重新固定 Ed25519 主机指纹，但未来 onboarding 若直接依次调用两个公开函数，会要求管理员对同一主机重复确认，也无法向交互层提供单一、稳定的准备结论。

这两项操作又有不同的回退性质：APT 安装不能由项目事务安全撤销；sing-box 准备只允许在目标不存在时原子安装，或对完全一致的目标幂等通过。因此统一编排必须固定先后顺序和失败短路，但不能把它们伪装成一个可回滚事务，也不能提前进入秘密、登记或 apply 阶段。

## 决定

新增保持 dormant 的 `controller_prepare_landing_readiness(address, ssh_port, landing_id)`。它只接受准备阶段必要的三个公开标识，并按以下顺序执行：

1. 验证本地固定参数、传输运行时、输入和入口控制器状态。
2. 验证 onboarding 日志路径；只要正式日志或 `.next` 存在，就在主机扫描和 SSH 前返回 `pending_recovery`，要求先收敛已有持久操作。
3. 发现一次 Ed25519 指纹并要求一次明确人工确认。拒绝返回状态码 2；确认器自身失败和用户拒绝分别报告。
4. 创建一个受管 0700 工作根目录，并在其中建立彼此隔离的 `dependency` 与 `singbox` 0700 子目录。
5. 把同一已确认指纹传给依赖准备的受信内部入口。该入口仍在 root 连接前重新扫描并固定指纹；任何失败都立即终止，绝不进入 sing-box 阶段。
6. 依赖返回 `ready` 或 `repaired` 后，才调用 sing-box 准备的受信内部入口。该入口使用独立子目录，并再次在连接前扫描和固定同一指纹。
7. 无论成功或失败都删除整个工作根目录；无法证明并完成清理时，顶层结果统一覆盖为 `local_cleanup_failed`。

门禁公开稳定结果：顶层阶段、已确认指纹、依赖状态与详情、sing-box 状态与详情、sing-box 版本和 SHA-256。顶层只描述编排停止位置，子阶段字段保留最精确的根因；未执行阶段保持 `not_checked`。这样交互层无需解析提示文本，也不会把前一阶段的成功误报为整体验证成功。

## 安全边界

一次人工确认不代表复用一次网络扫描。两个远程阶段分别重新扫描主机密钥，且只接受与人工确认值完全一致的 Ed25519 指纹；任一阶段发现变化都失败关闭。两个阶段不共享 `known_hosts`、响应或包文件，避免固定文件名覆盖以及前一阶段残留被后一阶段消费。

本门禁不创建或修改 controller 状态、每落地 SSH 密钥、密码、TLS 材料、onboarding 日志、受限账户、bootstrap 收据、配置包、AnyTLS 用户、systemd 单元或 nftables 规则。它不接角色路由、菜单、安装器、在线更新或服务器验收。APT 或 sing-box 在落地上的成功事实继续由各自 ADR 的幂等复检收敛，不新增持久准备日志，也不承诺事务回滚系统包。

## 与 onboarding 的关系

本决定先建立可独立验证的秘密生成前门禁；[ADR 0027](0027-readiness-gated-landing-onboarding.md) 已让统一 onboarding 入口复用本门禁确认的指纹，随后才创建持久日志和秘密。接线不在门禁后再次提示同一指纹，也没有把依赖或 sing-box 准备加入从 `credentials_pending` 开始的可回滚日志阶段。

## 验证与回退

定向测试覆盖单次确认、固定顺序、`ready`/`repaired` 继续、依赖失败短路、sing-box 失败、精确结果聚合、相同指纹传递、隔离的 0700 阶段目录、成功与失败清理、用户拒绝、输入与状态拒绝、待恢复日志门禁、本地运行时失败，以及清理失败覆盖。私有版与分享版运行同一测试；静态门禁证明函数仍未接菜单或角色路由。

接入 onboarding 前可直接删除本模块、测试和本文档，恢复模块清单与 CI 后重新生成两个单脚本。因为本阶段没有新增 schema、秘密或项目持久状态，不需要数据迁移；落地上已经成功准备的依赖和官方 sing-box 按 ADR 0024/0025 保留并可幂等复检，禁止为了代码回退盲目卸载系统包或删除未知已用二进制。
